# Production scene-construction submission assembly

This is the ADP-009D public-scene Day-28 rehearsal input boundary. The observed
completion artifact is a digest-bound, validated construction request and its
publication/readback receipt, followed by an authenticated Website preparation
receipt. None of those artifacts claims that native controls or policy episodes
have passed.

The existing construction/runtime engine remains authoritative. This module
joins the installed publisher sources, measured collision identities, a passive
destination candidate, owner task settings, and exact deployed release records.
It does not author substitute qualification results, allocate a provider, or
run a scene in an agent checkout.

## Production-only operation

Run the protected-main module on the production control plane:

```bash
python -m blueprint_pipeline.task_evaluation_scene_configuration_submission \
  --task-request <owner-task.json> \
  --installation-receipt <typed-installation-receipt.json> \
  --publisher-intake <pinned-publisher-intake.json> \
  --source-preparation-receipt <typed-source-preparation.json> \
  --destination-simready-result <destination-result.json> \
  --deploy-receipt <exact-production-deploy-receipt.json> \
  --release-provenance <verified-full-lane-provenance.json> \
  --release-environment <exact-release-environment-file> \
  --runtime-publication-root <production-system-runtimes> \
  --interiorgs-terms <retained-terms.pdf> \
  --interiorgs-readme <retained-publisher-readme.md> \
  --sage-readme <retained-sage-readme.md> \
  --staging-root <new-exclusive-staging-directory> \
  --expected-production-commit <full-current-protected-main-sha> \
  --namespace-timestamp <UTC-YYYYMMDDTHHMMSSZ>
```

Use the typed host-input intake and source-preparation producers for their
receipts. Do not hand-author a successful installation, geometry identity,
static/native qualification, or provider rights acceptance.

The task request explicitly selects the publisher scene ID, source subject and
support instances, destination relation/label, identities, positive timing and
motion bounds, zero retries/regrasps, and retained human processing authority.
The instruction is generated from these fields and any supplied instruction
must agree. Object names and dimensions are never universal runtime constants.

Provider retention and training-term acceptance must be explicit in the retained
human authority record. Scene selection alone is not provider disclosure
authority. Raw source uploads and provider training remain forbidden.

## Boundaries that must not be confused

- Current admitted appearance removal is `registered_source_bounds`: a
  registered bounding-box cutout and projected bounds masks. The task must select
  this method explicitly. SAM3.1 accepted-track/exact-mask requests fail before
  staging until their typed production route is wired; the assembler must not
  silently substitute bounding boxes.
- The passive destination is a statically qualified candidate. Native import,
  scene placement, contact, reset and camera qualification remain pipeline stages.
- The task documents preserve existing immutable candidate-preregistration
  statuses, not native qualification. The strict owner-contract requirement
  survives native adaptation; policy setup must not replace it with legacy
  compatibility scoring.
- Source-only pre-render validation is separate from actual render-input
  admission. A candidate mask identity is not fabricated to pass a renderer gate.
- An explicit instruction survives native adaptation with its configured subject
  and destination labels.

## Publication and submission

The output manifest inventories every retained file with exact digest and size.
Raw-source rows retain original revision-pinned publisher URLs and
`publication_allowed=false`; they are not object-store upload candidates.
Use the operator-owned [installed-source binding](task_evaluation_installed_publisher_sources.md)
for production preparation to read these exact bytes on the host. Do not seed
caches by hand, open broad URL allowlists, or enable raw uploads.

Publish the admissible configuration/derived inputs with full byte readback.
Only then use `scripts/submit_task_evaluation_preparation_via_webapp.py` with the
canonical production secret-file reference and an exclusive receipt output.
Do not treat an assembler result as a Website submission or a provider launch.

Focused tests cover digest/scene/release mismatches, source/support isolation,
destination fit, raw-upload exclusion, explicit authority, method refusal,
native-adapter compatibility, and prevention of legacy scoring fallback.
