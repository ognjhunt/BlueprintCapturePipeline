# MuJoCo ⇄ Isaac parity — execution backlog (tracked tasks)

Each task below is grounded in current code (file:symbol verified), has objective acceptance criteria, and a GPU-free verification command. **This file is the durable source of truth** for the autonomous loop.

## How the loop works (protocol)

When given the goal command, on each iteration:

1. Read this file. Pick the **lowest-positioned task whose `Status:` is `todo` and whose every dependency is `done`** (skip `blocked`/in-progress-by-others).

2. Set that task's `Status:` to `in-progress`.

3. Implement it per its Files/Steps. Keep world-model backends swappable; never let one lane's evidence stand in for the other (MuJoCo evidence ≠ Isaac evidence).

4. Run its **Verification** command. It must pass (GPU-free unless the task explicitly says a GPU run is required — in that case run the hermetic partial-check and mark `Status: done (gpu-pending)`).

5. On green, set `Status:` to `done` and check off its acceptance criteria. Commit the change on a feature branch (do not push unless asked).

6. Repeat until **every** task is `done`. Stop when no `todo` remains, or when a task is genuinely `blocked` (record why under its **Blocked** line).


Legend — Status values: `todo` · `in-progress` · `done` · `blocked`. Effort: S/M/L. Lane: MuJoCo / Isaac / Shared.

**Dependency notes:** The backlog is a clean DAG with three edges and eleven independent roots. T4 (Isaac learned-policy requery on the WAM-generated observation) is a fan-out hub unlocking both T5 (honest completion gating + in-loop drift reanchoring) and T6 (in-process manipulation success evaluator): you cannot strengthen completion gates to require fresh learned-policy requery counts, nor emit a genuine success label, until the policy is actually requeried in-loop. T13 (Isaac gravity-on dynamic stepping with displacement + fall verdict) unlocks T14 (torque/effort PD drive + authored MassAPI/PhysicsMaterial), since force-level contact realism is only provable once the gravity-on settle emits a physics_integrated verdict. Everything else — T1, T2, T3, T7, T8, T9, T10, T11, T12, T15 — is an independent root with no dependencies.

**Sequencing rationale:** Topology is satisfied: T4 precedes T5 and T6; T13 precedes T14; no cycles. Within the freedom the DAG allows, I front-load the cheapest cross-lane evidence wins that the task specs themselves flag as unblocking — T1 (S, "cheapest cross-lane win," camera contract for calibration/target-in-view), then the small/medium native depth passes T3 (S, Isaac) and T2 (M, MuJoCo) which both lanes need and which other modality work builds on. Next comes the single highest-value correctness gap, T4 (L), the actual purpose of the Isaac eval (policy-on-generated-world), immediately followed by its now-unblocked cheap honesty payoffs T5 (S, completion gating) and T6 (M, success evaluator). Then the shared photoreal handoff T7 (M) and the small render-fidelity narrowers T11/T12 (S MuJoCo texture+lighting), followed by the paired segmentation passes T8/T9 (M each). The Isaac physics chain T13→T14 lands later because T14 is an L force-level task and is gated by T13. The two remaining medium MuJoCo fidelity items (T10 collision proxies) and finally the large, explicitly "last, not correctness" ops-convergence item T15 close out the list, matching the report's section-7 roadmap intent of deferring cost/ops work behind correctness work.
