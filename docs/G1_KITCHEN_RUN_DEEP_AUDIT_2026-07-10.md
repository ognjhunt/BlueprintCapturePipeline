## Executive verdict

There is no end-to-end successful G1 kitchen manipulation run in the audited
artifacts.

The strongest live result is a RunPod RTX A6000 startup/RTX pixel canary. The
strongest kitchen results load the full scene, render G1 and task media, and
accept portions of stance/target grounding. None proves that a fresh
`UNITREE_G1_SONIC` action was decoded by the official GEAR-SONIC controller,
applied to a persistent Isaac scene, changed a registered kitchen articulation,
passed strict forward and inverse action consistency, and satisfied semantic

## Truth boundary

This is a simulation-only audit. It does not require or claim physical G1
readiness, deployment approval, real-world safety, or real-robot task success.
Physical validation is a future claim-upgrade lane, not a blocker for closing the
simulator lane.

The following labels are invalid shortcuts:

- `marker_verified` is not Isaac completion;
- `isaac_g1_kitchen_parity_result.status=completed` is not manipulation success;
- `robot_policy_wam_loop_manifest.status=completed` is not task-state success;
- video temporal change is not forward or inverse action consistency;
- a generated-video semantic label is not simulator articulation proof;
- a local dry-render schematic is not an Isaac RGB observation;
- policy-server output is not controller/FK or simulator execution proof.

## Detailed findings and implementation specifications

### G1K-P0-01: Build one attempt-bound closure manifest

Severity: Critical  
Category: proof integrity / orchestration  
Primary files:

- `src/blueprint_pipeline/oscar_isaac_closed_loop_eval.py`
- `src/blueprint_pipeline/isaac_g1_kitchen_parity_job.py`
- `src/blueprint_pipeline/groot_oscar_digitalocean_closed_loop_job.py`
- `src/blueprint_pipeline/unitree_groot_n17_sonic_vast_persistent_session.py`
- `src/blueprint_pipeline/mujoco_g1_wam_vla_policy_endpoint_eval.py`

Problem:

Different manifests use `completed` for provider, renderer, structural loop, or
evaluator execution. There is no authoritative attempt rollup that requires all
sim-only proof layers and marks old `waiting_for_marker` records terminal after
teardown.

Required implementation:

1. Add `g1_kitchen_attempt_closure.v1` keyed by immutable run ID, attempt ID,
   launch nonce, source commit, image digest, bundle digest, kitchen asset digest,
   active selection SHA, task contract SHA, and provider allocation ID.
2. Record independent tri-state rows (`passed`, `blocked`, `not_requested`) for:
   allocation, startup, fast canary, review canary, asset gate, scene load, target,
   stance, collision, robot POV, controller/FK, persistent simulator transition,
   semantic review, forward consistency, inverse consistency, teardown, and final
   inventory.
3. Overall status is `completed` only if every required row passes.
4. A superseded or torn-down attempt must receive a terminal normalized record;
   do not leave `waiting_for_marker` as the latest truth.
5. Downstream buyer/readout code must consume this closure artifact rather than
   infer success from leaf `status` fields.

Acceptance tests:

- A renderer-completed/task-not-proven fixture is overall `blocked`.
- A structural-loop-completed/fixture-perception artifact is overall `blocked`.
- A marker-verified/no-worker-result artifact is overall `blocked`.
- A fully passing synthetic contract closes only with API-confirmed teardown.
- Duplicate run/attempt IDs or mismatched nonce/digest/selection hash fail.

## External research applied

- [NVIDIA Isaac Sim requirements](https://docs.isaacsim.omniverse.nvidia.com/5.0.0/installation/requirements.html)
  state that GPUs without RT cores such as A100/H100 are unsupported. This
  supports a capability gate that separates compute-only policy workers from
  RTX review-render workers.
- [NVIDIA Isaac Sim container installation](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/installation/install_container.html)
  requires NVIDIA Container Toolkit, recommends compatibility checking, and
  describes headless-container constraints. The production canary should run
  the compatibility check or equivalent structured checks before review work.
- [NVIDIA Isaac-GR00T policy documentation](https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/policy.md)
  identifies `UNITREE_G1_SONIC` as a post-training embodiment tied to GEAR-SONIC
  WBC. The policy server therefore cannot substitute for controller execution.
- [NVIDIA GR00T Whole-Body Control](https://github.com/NVlabs/GR00T-WholeBodyControl)
  is the authoritative source tree for the GEAR-SONIC controller/deployment
  stack that the sealed adapter should wrap.
- [RunPod Pod creation API](https://docs.runpod.io/api-reference/pods/POST/pods)
  documents availability-prioritized GPU selection and the distinction between
  container and persistent volume storage. Only a successful create response
  proves allocation.
- [RunPod pricing](https://docs.runpod.io/pods/pricing) documents per-second
  compute/storage billing and continued stopped-volume charges. Terminal delete
  and explicit storage accounting are appropriate.
- [DigitalOcean GPU Droplets](https://docs.digitalocean.com/products/gpu-droplets/)
  distinguishes AI/ML-ready images with drivers from custom images that require
  manual driver setup.
- [DigitalOcean regional availability](https://docs.digitalocean.com/platform/regional-availability/)
  shows GPU plan availability varies by GPU family and region; regional plan
  visibility is not a reservation.
