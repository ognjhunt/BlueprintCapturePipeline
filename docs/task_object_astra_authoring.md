# Astra task-object authoring

This is the ADP-009 development-only construction dependency for the day-14
scene rehearsal and day-21 two-policy diagnostic. Completion evidence is a
retained authoring program, exact-dimension mesh and USDZ, source comparison
images, independently reviewed physical estimates, and native scene readback.
Authored assets do not establish physical truth or native qualification.

The prior Content Agents material path could receive inadequate source context
and produce opaque-object material defects. The optional
`astra_cad_blender_v1` backend consumes the actual admitted source frames and
their hashes, preserves exact source/design dimensions, executes the pinned CAD
skills and Multi-Agent-CAD graph, and runs a headless Blender appearance pass.
An independent appearance review gates the result. A separate physical-property
review preserves measured values and labels estimates with ranges and evidence.

## Production selection and runtime

New task materialization selects `astra_cad_blender_v1` by default and records
the choice in its immutable stage-three configuration. An explicitly selected
`content_agents` backend remains available for compatibility. Previously sealed
stage configurations without the field retain their original execution route;
old completed stages remain eligible for digest-verified adoption.

Deploy with `scripts/deploy_control_plane_commit.py --astra-blender-archive`
pointing at the verified official Linux archive. The release builder seals
Blender with the CAD sources and the `astra_asset_authoring` Python wheelhouse.
The provider installs only those locked wheels and runs an isolated import
preflight. An Astra configuration with a legacy toolchain refuses before bundle
creation. Deployment itself grants no model-call or GPU authority.

The existing single-use parent authority still controls spend. An uncompleted
Astra authoring stage requires a stage allocation of at least USD 5; it is also
bounded by the parent external-service cap and the USD 15 authoring ceiling.
The backend does not raise an existing cap. A completed adopted authoring stage
requires no new authoring allocation. API transport retries are disabled, and
unpriced failed requests retain their full reservation. Stable instruction
prefixes use explicit prompt caching; receipts record actual writes and reads.

## Asset and recovery boundaries

Generated programs run under an OS sandbox without credentials or network.
Blender strips author-suggested dynamics before export. Packaging derives the
collision geometry, center of mass, and inertia from the final evaluated visual
mesh, and applies only independently accepted physical properties. Native
import, collision, settling, visibility, and placement checks remain required.

The worker can adopt completed source analysis, CAD planning/code, physical
review, and Blender programs. Adoption verifies the unchanged request inputs,
retained output hashes, and completed provider-response digests. This avoids
repeating successful paid phases when a local execution boundary fails. Saved
failures remain evidence; a render or provider response alone is not completion.
