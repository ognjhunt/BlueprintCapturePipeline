# Website task-object authoring session

ADP-009B / day-21 construction rehearsal. The observed blocker was the website
object authoring path's fixed sequence of one-turn calls: an ordinary compiler
failure stopped authoring instead of returning to an agent that could repair it.
The completion artifact is the independently accepted
`task_object_astra_authoring_result.v1`, still `development_only` and pending
native import and scene placement. This change does not qualify the room.

Fresh `website_capture_frames` requests now use one local Agents SDK
conversation per object. The author receives the admitted original stills,
task, nominal dimensions, uncertainty and any generated-variant specification.
It can record its interpretation, compile a complete build123d program through
the pinned CAD CLI, run the existing sandboxed Blender/USD exporter, and inspect
three generated studio views. Compiler and render errors return to the same
conversation. The CAD graph's separate model calls are not nested inside these
tools; source pins, sandbox and deterministic readback remain enforced.

Independent physics and appearance reviewers accept or return corrections.
The author cannot set readiness, choose a robot/policy, alter spending, or rent
a GPU. Existing static and native qualification remain downstream. Previously
completed/partially adopted legacy phases retain their existing adoption path.

Each actual SDK model request passes through the existing stage invoker and
durable inference ledger before transmission. The adapter counts the complete
local conversation, tool schemas and actual image dimensions, reserves that
request's maximum, and reconciles its returned usage. Failed/uncertain calls
retain their full reservation. The existing stage dollar limit and shared
15-request maximum cover authoring and independent reviews together. Hidden
server conversation state, hosted tools and transport retries are refused.
This avoids reserving all possible future turns at their full ceiling before
any actual request, which would otherwise unnecessarily exhaust the $5 stage.

Conversation and tool outcomes live under `inference/asset_session`, outside
the generated program's writable sandbox. A repeated tool-call ID reuses its
saved result; an ambiguous interrupted tool call refuses. Model-declared
completion without validated artifacts cannot produce an accepted result.

The separate initial-authentication recovery recognizes the retained first
401/expired-key failure only when the bound archive proves no preceding model
completion, no paid preparation, and no GPU allocation. It keeps the rejected
call's entire projected charge until billing settles, authenticates a changed
key in the same project, and uses the existing controller recovery/budget path.
Historical receipts and owner caps are unchanged.

Verification uses the actual SDK Runner with scripted provider responses and
fake CPU tools: compiler failure/repair, original and generated image history,
independent rejection/repair, model false-success refusal, budget and call-count
refusals, duplicate tool handling, artifact tampering, and controller dispatch.
These tests prove orchestration contracts; they are not live blue-object CAD,
Blender, native simulation or final provider billing evidence.
