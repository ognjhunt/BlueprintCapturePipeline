# Private team evidence in daily research

`team_universe/evidence_export.py` projects the exact current audited rank v2 into a contact-free
`blueprint.team-evidence-export.v1`. It recomputes every rank row from the current retained discovery,
screen and independently reviewed manual audit. The export binds the original rank bytes, audit,
all canonical source identities, qualification rules, assessment date and projected row digest.
Raw vocabulary signals, funding, company names, invitation or API labels never establish qualification.

Only a source-supported current physical robot/control/integration offering with explicit hardware,
physical task, owned offering relation and verified company identity becomes `capability_prospect`.
Every canonical row remains available: adjacent/reference, unresolved and unscreened entries are held,
not recommended candidates. Blueprint compatibility and partner intent remain separate unknowns;
no row becomes confirmed, evaluation-ready, a relationship or authority for contact/spend/send.

The offline `tools.team_universe.cli export --out PRIVATE_WORKSPACE --audit REVIEWED_AUDIT
--destination PRIVATE_OUTPUT` command writes an exclusive mode-0600 output outside Git repositories
and volatile directories. It makes no page/provider calls. Real data never belongs in public fixtures.
The compact canonical UTF-8 encoding is required so the original export digest is reconstructible.

`operators/team-universe-evidence.py publish --file PRIVATE_OUTPUT` and `pin --sha256 DIGEST
--generation GENERATION --approval-reference OWNER_RECORD --expect-current none` are read-only
plans by default. Only explicit `--apply` publishes/pins. Publication uses the existing company bucket,
content-addressed `operations/research/team-universe/DIGEST/evidence.v1.json`, create-only generation
preconditions, private cache policy and exact-byte readback. Pinning uses the existing fenced lease,
checks no active/queued daily research, QA, repair or publication before and under that lease, CAS-swaps
only `control.team_universe`, appends a monotonic version receipt, then reads back. There is no active-run
bypass, new credential, provider, paid flag, schedule or outreach setting. A source/release repin and
team-data pin must use separate explicit lease ownership; no unrelated control fields change.

For a new daily intent, `FirestoreLedger.team_universe_snapshot` reads the exact generation once.
The host validates all safe fields, source digests, structural proof anchors and currentness before
freezing `/workspace/inputs/blueprint-team-evidence.json`, its SHA256 and pin in that durable intent.
Only a run with a successfully frozen attachment exposes the free `blueprint_read_team_evidence`
tool in its search profile. It reads only those
frozen bytes, optionally filtering an exact stable `team_key` or task family. Byte-based pagination
preserves every canonical row; there is no recommendation quota. Recommendations record stable ID,
rationale, cited hardware/task/offering proof URLs and hashes, date/freshness and remaining unknowns
in existing findings/next-action strings. Tool results have ordinary durable receipts and add no paid
search request. A separately recorded currentness hold keeps expired historical offerings visible.

An unconfigured or disabled pin preserves the exact legacy intent, tool registry, row, store and
status; `show` diagnoses that host state. A configured but unavailable, invalid or oversized input
records an actionable supply gap and continues ordinary authorized research without adding the
reader. Expired physical proofs in a valid historical export remain attached but explicitly held
and never eligible for recommendation. Neither path fabricates eligible supply or blocks an
otherwise valid run.
Byte/schema resource ceilings apply, and the pin plan exercises the actual bounded freeze before
claiming ready. Current pins cannot rewrite older intents or their frozen team input. `show` and the
normal runner status report only pin/digest/state/counts, never private team rows. Dataset semantic
review and exact source/data pin readback remain publication gates owned by the release operator.
