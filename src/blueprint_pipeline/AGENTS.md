# Agent Guide For `src/blueprint_pipeline/`

This package contains materialization, package assembly, provider adapters,
privacy and geometry lanes, runtime support, launch gates, and WebApp sync. Two
programs are active, the free beta's job packet (owner direction 2026-11-12)
and Arm Decision Proof v1; other lanes remain compatibility unless a recorded blocker in
one of them requires their smallest reusable component.

Beta work builds the Pipeline's part of the job packet from retained job video:
the simulation of the site with the job's object in it, the success rule and,
where one exists, the early trial. Reuse
existing evidence and run the supported configurations or the smallest
qualified test that resolves material uncertainty. Existing licensed Blueprint-managed
execution and approved team-supplied endpoints remain valid. Preserve
independent scoring and controlled observations. The early trial is supporting
evidence, never the site's answer; responses of deployment companies cannot
create scientific authority.
ADP work converges on one
partner-owned fixed-arm task, two frozen
candidates, a qualified candidate MSER, complete condition-level receipts, a
sealed prospective decision, and an exact held-out Physical Outcome Join.
Existing fixtures/scenes may exercise these seams only as `development_only`.

Keep raw capture truth, canonical package truth, provider-preview projection,
hosted-review projection, and gate snapshots separate. Compatibility fields with
`qualification` names may remain, but they are support artifacts rather than the
product center.

Do not hardwire Blueprint to one provider, checkpoint, GPU path, or hosted
service. Do not promote fallback geometry, raw provider bypass, mocked Stripe,
missing SDK env, or automated contract checks into live launch proof.

For owner-authorized website reconstruction, use the selected provider/model's
configured, verified maximum input image count, or all distinct available frames
when fewer exist. Never impose a global eight-image or 100-image ceiling: Atlas
and future providers may accept 100+ images. Keep this capacity in provider data,
and keep reconstruction context sampling independent of the geometry/GPU batch.
Retain task views and wider room context; frames need not show the task object.
Edit only selected task-object regions and review the complete selected view set.
